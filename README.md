# BioTime Employee — Android WebView + фоновый трекинг

Нативное Android-приложение-обёртка вокруг BIOTIME: открывает приложение во весь
экран (WebView) и обеспечивает **фоновый трекинг геолокации водителя 24/7** —
даже когда приложение свёрнуто или экран заблокирован.

## Что делает

- Открывает `https://app-0cd4491f8939.vibecode.bitrix24.tech/` (адрес BIOTIME-приложения).
- Каждые **15 секунд** отправляет координаты водителя на готовый серверный
  эндпоинт `POST /api/drivers/location`.
- Работает в фоне через **Foreground Service** (постоянное уведомление).
- Подхватывает активный маршрут (`routeId`) из WebView и шлёт его вместе с
  координатами, чтобы карта показывала «Маршрут N».
- Перезапускается после перезагрузки устройства и включения GPS.

## Как собрать APK

1. Установите **Android Studio** (бесплатно, https://developer.android.com/studio).
2. Откройте папку `android/` как проект (File ▸ Open).
3. Дождитесь синхронизации Gradle (скачает плагины/зависимости).
4. Соберите отладочный APK:
   - в Android Studio: **Build ▸ Build APK(s)**, либо
   - из консоли: `./gradlew assembleDebug`
5. APK появится в `app/build/outputs/apk/debug/app-debug.apk`.
6. Распространите водителям (подпись/публикация на Google Play — отдельный шаг,
   нужен Play Console аккаунт; для внутреннего использования достаточно
   скачать APK напрямую на устройства / внутреннее тестирование).

## Онлайн-сборка без Android Studio (GitHub Actions)

Проект уже содержит готовый workflow: `.github/workflows/build-apk.yml`.
APK собирается **в облаке GitHub** — не нужно ничего устанавливать локально.

Как включить:

1. Создайте репозиторий на GitHub (public или private — private бесплатен
   для небольших команд) и залейте в него **содержимое папки `android/`**
   (settings.gradle.kts, build.gradle.kts, app/, gradlew, gradlew.bat и т.д.)
   как корень репозитория.
2. Запушьте — workflow «Build APK» запустится автоматически.
3. Вкладка **Actions ▸ последний запуск ▸ Artifacts ▸ `biotime-apk`** —
   оттуда скачивается готовый `app-debug.apk` и `app-release.apk`.
4. Пересобрать вручную — кнопка **Run workflow** на той же странице Actions.

release-APK подписан отладочным ключом (см. `build.gradle.kts`), поэтому его
можно сразу установить. Для Google Play позже добавьте настоящий keystore.

## Первый запуск — что спросит приложение

При первом запуске приложение последовательно запросит:

1. **Доступ к местоположению** (во время использования / на устройстве) —
   обязательно «Разрешить».
2. **Уведомления** — за ними живёт постоянное уведомление о трекинге.
3. **Доступ к местоположению «всегда»** (Android 10+) — отдельный экран,
   выберите «Разрешить всё время». Без этого фоновый трекинг не работает.
4. **Исключение из энергосбережения** — подтвердите, иначе система остановит
   фоновый трекер через несколько минут.

Если какой-то шаг пропущен — включите вручную:
- Настройки ▸ Приложения ▸ Личный кабинет сотрудника ▸ Разрешения ▸
  Местоположение ▸ **«Разрешить постоянно / все время»**.
- Настройки ▸ Приложения ▸ Личный кабинет сотрудника ▸ Батарея ▸
  **Не ограничивать / Без ограничений**.

## Проверка трекинга

1. Выполните вход водителя в приложении (WebView), закройте его.
2. На BIOTIME (вкладка «Трекинг») админ должен видеть зелёную метку водителя,
   которая движется каждые ~15 сек.
3. Сверните приложение и подвигайтесь — метка должна продолжать двигаться.

## Известные нюансы

- **Android энергосбережение** — главный враг фонового трекинга. Без исключения
  из оптимизации battery система может усыпить сервис на некоторых брендах
  (Xiaomi, Huawei, Samsung). Пункт 4 выше обязателен.
- **Если сессия истекла** (водитель долго не заходил в приложение) — фоновый
  запрос вернёт `401/403`, и координаты перестанут доходить, пока водитель не
  откроет приложение и не войдёт заново.
- **Мост routeId**: веб-код должен звать `AndroidBridge.setRouteId(...)` при
  входе в активный маршрут, чтобы карта показывала название маршрута у метки.
  Если мост не вызывать — трекинг всё равно работает, просто без имени маршрута.

## Настройка перед релизом

- Проверьте, что в `MainActivity.kt` константа `APP_URL` указывает на актуальный
  адрес BIOTIME-приложения.
- При желании замените пакет `com.biotime.employee` (applicationId) на свой,
  например `ru.company.biotime`, и обновите namespace — это меняется в
  `app/build.gradle.kts` и в путях Kotlin-файлов.
- Замените иконку-заглушку на фирменную (drawable/ic_launcher_foreground.xml).
